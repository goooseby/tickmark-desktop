# 设备与统计报表规则

## DATA 设备和区间

- **DATA-01 设备身份**。每台设备独立拥有稳定 ID。同类设备可以有任意台，显示名和平台只用于识别。源接口返回 `devices[]`，包括 `id`、`name`、`kind`、`platform`、`local`、可选 `revision`、`updatedAtMs` 与 `rows[]`。本机入口当前使用保留 ID `local-windows`。进入多台 Windows 同步前，为每台安装生成持久 ID，解决本机库与远端镜像对同一设备的映射。
- **DATA-02 区间**。区间使用 UTC 毫秒和左闭右开 `[startMs, endMs)`，同设备内区间互不重叠。状态 `0` 活跃、`1` 暂停、`2` 离线、`3` 采集缺口。空白代表缺少记录。应用仅在一个明确的跨端标识 `sharedAppId` 存在时跨端合并。同名应用、同名文件不能自动归为同一个实体。
- **DATA-03 本地镜像接口**。在 Tickmark 数据目录的 `report-devices/` 下，每个外部设备对应一份 `<id>.json`。ID 使用 1 至 80 位小写 ASCII 字母、数字、下划线或连字符。文件上限 16 MiB。读取时校验身份、时间边界、状态和重叠，单个坏文件在「设备与规则」计数。向镜像写入的程序应先生成完整临时文件，再同目录原子替换。此入口供数据工具或未来同步接入，当前桌面端只有读取。尚无自动导入 Android 报告的适配器。

示例使用固定历史时间，放入 `report-devices/study-tablet.json` 后可在相应日期查看。

```json
{
  "id": "study-tablet",
  "name": "学习平板",
  "kind": "tablet",
  "platform": "Android",
  "revision": 1,
  "updatedAtMs": 1795521600000,
  "rows": [
    {
      "startMs": 1795521000000,
      "endMs": 1795521600000,
      "state": 0
    }
  ],
  "appRows": [
    {
      "startMs": 1795521000000,
      "endMs": 1795521600000,
      "state": 0,
      "appId": "example.reader",
      "appName": "阅读器",
      "page": "课程材料.pdf",
      "pageKind": "document"
    }
  ]
}
```

`rows` 是设备状态区间，`appRows` 是应用会话；两者都使用 UTC 毫秒和左闭右开区间。文件名必须与设备 `id` 一致，例如 `study-tablet.json`。`appRows` 可省略；省略时界面回退到 `rows` 读取应用字段，但带设备状态的多设备报告建议分开提供。

## AN 统计口径

| 规则 | 定义 |
| --- | --- |
| AN-01 去重用时 | 所选设备活跃区间的并集。任一设备活跃即可贡献时间。 |
| AN-02 设备累计 | 各设备活跃用时之和。同一分钟可以被多台设备各记一次。应用、文档与站点榜采用此口径。 |
| AN-03 同时使用 | 至少两台所选设备同时活跃的时间。三台共同活跃一分钟，对总重叠只贡献一分钟。两两配对表分别计该对设备共同活跃的用时，同一分钟可以出现在三行中。 |
| AN-04 覆盖率 | 活跃、暂停、离线的区间总和 ÷ 所选时期已过去的时间。采集缺口与无记录各自展示。只有暂停或离线时，活跃为零。整段无观测时，活跃统计为未知。多个来源部分缺失时，页头指标仅反映已记录的区间。 |
| AN-05 自然日 | 使用桌面当前显示时区切分日期。跨午夜按边界裁剪，变更显示时区会重新分桶。周使用周一至周日，月使用自然月。当前日截到现在，未来日期跳过覆盖和每日明细入口。 |
| AN-06 小时活跃分布 | 跨日累计本地 00–23 点中已观测时段与活跃时段的并集，再取比值。夏令时重复小时合并到同一时钟标签，缺失小时没有样本。 |
| AN-07 明细与归属 | 站点按域名累计。文件以应用身份加文档名累计，防止不同软件中的同名文档合并。应用至少有一条已识别明细且有未分配时长时，才显示「页面未识别」。 |
| AN-08 查询一致性 | 周月、日报、记录明细从同一批区间读取，先裁剪再聚合。记录明细的防抖折叠、时间轴的短切换平滑和无活动区间压缩都属于展示，底层区间保持不变。待接入命令行时，机器输出包含范围、时区、设备与覆盖口径。 |

## UX 报表界面

| 视图 | 常用操作 | 核对入口 |
| --- | --- | --- |
| [多设备仪表盘](multi-device-dashboard.md) | 默认入口。当天去重摘要、首屏多设备时间轴、设备用时饼图、跨设备应用榜和本周上下文。 | 点轨道选区或色块进入对应范围记录明细，点应用来源查看设备记录，点「查看趋势」进入周月分析。 |
| 今日复盘 | 分时卡按凌晨、上午、下午、晚上展示活跃用时和主要应用。色带显示应用时长占比，无应用明细的时段收为简短状态。应用行显示设备名或设备数量。 | 点时段进入对应记录明细，展开应用回看站点或文档。应用并行时分别计入各自的时长，卡片活跃用时按设备区间去重。 |
| 记录明细 | 不占主导航，从时间轴选区、今日复盘或设置进入。默认应用会话，可切换设备记录；按状态和设备筛选，折叠短切换。 | 核对起止、设备及原始页面；返回按钮回到进入前的页面与范围。 |
| 趋势 | 周月切换，设备筛选联动整页。每日趋势切换按设备堆叠或去重及重叠。小时分布、三类排行、覆盖和设备组合按同一范围刷新。 | 每日明细列出各台设备用时，点日期进入该日记录明细并继承设备筛选。覆盖表解释缺口，配对表解释多设备同时使用。 |
| 设置 | 查看本机采集、浏览器扩展与账号同步状态、数据库体积和其他设备；管理文档标题记录。 | 可对照设备更新时间、校验异常数量与应用开关。 |

只有一台设备或汇总筛选到一台设备时，页头使用活跃、暂停、离线和采集覆盖，趋势和每日明细聚焦该设备用时。

## 待实现的分析与查询

1. **前后周期对照**。自然周对上一周，自然月对上一月。当本期未结束时，上期只比较等长的历时时段。设备筛选在两期一致。两期的覆盖不足时显示缺少的数据范围，避免把数据延迟解释成使用变化。
2. **应用与站点钻取**。从榜单进入来时设备、逐日趋势、覆盖率和带证据区间的记录明细。应用详情可切换各设备占比。站点在多个浏览器中出现时显示浏览器来源。支持复制当前时段的查询参数。
3. **时段对比**。能按工作日／周末或自选时段比较。按活跃时长、使用次数及最长连续段排序。连续段在活跃状态改变或应用切换时终止，期间缺口保留为边界。该功能的目的为查阅行为记录。
4. **并行组合下钻**。从配对行跳到共同活跃区间，同时定位各设备当时的应用。支持显示并发数和时间顺序。
5. **命令行与导出**。按日期区间、时区、设备、应用、域名及状态过滤。输出区间或聚合表，返回覆盖元数据及毫秒数。抽取共享计算模块后，与 UI 使用相同边界测试再交付。
6. **聚合型来源**。只提供小时或日总量的设备可以加入累计视图。精确去重、重叠和时刻对账需要原始时间段。同步界面明确最新修订和最后覆盖时间。
