# Windows 应用与页面使用计时设计

2026-11-25 · 设计定稿（v1.1）

## 1. 核心目标与基本原则

本工具用于回答两个核心问题：**在指定时间段内，每个 Windows 软件在前台用了多久？其中具体在看哪个网页、写哪份文档？**

- **单前台原则（绝不重复算时间）**：同一时刻、同一 Windows 登录会话内，**最多只归属一个前台应用**。双屏并排显示、画中画视频、后台下载、后台听歌或挂着语音通话，均不额外叠加第二份应用时长。
- **层级包含原则**：某款软件的总时长，等于其下「已识别页面/文档时长」与「未识别明细时长」之和。明细是总时长的向下拆解，不会超过软件总时长。
- **本地隐私原则**：所有窗口标题清洗、网址脱敏都在本机实时完成。键盘输入内容、剪贴板、屏幕截图、未授权的窗口标题、完整 URL 参数与隐私模式浏览记录，一律不入库。

## 2. 统计口径与四种状态

时间轴上的每一秒，都会被明确归入以下四种状态之一，方便后续统计与对账：

| 状态 / 指标              | 人话口径                                                     | 计入使用时长？ |
| ------------------------ | ------------------------------------------------------------ | -------------- |
| **正常计时 (`ACTIVE`)**  | 屏幕亮着、未锁屏，当前有明确的前台软件，且未触发无操作暂停。 | **计入**       |
| **无输入暂停 (`IDLE`)**  | 超过 2 分钟没有任何键鼠操作（且当前不在看视频），判定人已离开电脑。 | 不计入         |
| **不可计时 (`OFFLINE`)** | 明确处于锁屏、息屏、睡眠、休眠或注销状态。                   | 不计入         |
| **采集缺口 (`GAP`)**     | 程序异常退出、电脑强制断电或系统事件丢失，导致中间一段状态无法还原（如实留白，绝不瞎猜补全）。 | 不计入         |

> **特殊场景说明**：当前台是远程桌面（RDP）或虚拟机窗口时，本机把时间记在远程桌面/虚拟机软件上；若远端系统也装了本采集器，两边各自独立记录，互不覆盖。

## 3. Windows 前台感知与防抖策略

桌面端窗口切换极快，弹窗和系统面板多。为防止时间轴被切得稀碎，采用“底层防抖 + 上层合并”双层过滤：

1. **实时监听 + 定时兜底**
   - 通过系统钩子 `SetWinEventHook(EVENT_SYSTEM_FOREGROUND)` 实时捕获前台窗口切换；程序启动、休眠唤醒及每隔数秒，调用 `GetForegroundWindow()` 校准一次当前状态，防止系统漏发事件。
2. **第一层：采集防抖（过滤 2 秒内的纯噪音）**
   - 按下 `Alt+Tab` 切屏界面、点开音量/输入法面板、或一闪而过的系统提示框，只要停留时间 **不足 2 秒** 且随后切入了正常软件，这段切换过程直接吞掉，时间归入上一个正常软件，不单独切分时间段。
3. **第二层：展示合并（折叠 5 秒内的短暂插曲）**
   - 停留 **2 ~ 5 秒** 的真实切屏（例如写论文时切去微信瞄一眼消息、切去浏览器复制个链接再切回来），底层数据库如实记录；但在日常统计图表和明细列表里，默认把这种不足 5 秒的短暂跳转自动折叠进前后的主任务中（支持手动展开查看原始明细）。
4. **电源与会话状态监听**
   - 订阅系统会话通知与电源广播：一旦收到**锁屏、息屏、注销、睡眠/休眠**通知，当前计时段立刻封口，状态转为 `OFFLINE`；直到解锁亮屏后重新检测到操作，才开启新一段计时。

## 4. 无输入自动停表规则（含视频/放映豁免）

把计时器看作一个 **“2 分钟（120 秒）续命倒计时”**：

Plaintext

```
1. 正常操作（亮屏、未锁屏、有键鼠输入）：
   状态设为 ACTIVE，剩余倒计时重置为 120 秒。

2. 停止键鼠操作：
   倒计时开始往下减。
   - 归零前又有键鼠操作 -> 计时没断过，倒计时重新拉满 120 秒。
   - 连续 120 秒无键鼠操作 -> 倒计时归零，立刻暂停计时（状态转为 IDLE），多一秒都不算，直到下次键鼠操作才恢复。

3. 前台视频 / 放映豁免（关键例外）：
   满足以下任一条件时，倒计时保持满格不扣减，即使全程不碰键鼠也持续正常计时：
   - 前台浏览器明确报告视频正在播放；
   - PowerPoint 正在全屏放映。

   音乐、语音会议和普通有声应用不豁免；不能仅凭“有声音”判断为视频。浏览器或播放器无法提供明确播放状态时，按普通 120 秒规则处理，不猜测。

4. 切换窗口或页面：
   不重置倒计时，仅将后续流逝的时间归属切换到新窗口/新页面名下。

5. 锁屏 / 息屏 / 睡眠：
   无视剩余倒计时，当场清零并暂停（状态转为 OFFLINE）；恢复亮屏后不自动开表，必须等下一次真实键鼠操作才重新启动计时。
```

**工程实现校准要求**：因为 Windows 的 `GetLastInputInfo` 是被动查询接口，**每次收到窗口切换、锁屏等系统事件时，在结算上一段时长之前，必须先主动调用一次 `GetLastInputInfo` 获取真实的最后硬件输入时间**，避免轮询间隔导致停表时刻算偏。

### 规则对照示例（假设 10:00:00 操作了一次，停表截止线为 10:02:00）

| 接下来发生什么                         | 实际怎么记                                                   |
| -------------------------------------- | ------------------------------------------------------------ |
| **10:01:30** 又动了鼠标                | 前 90 秒全算；停表截止线顺延到 **10:03:30**。                |
| **10:02:00** 整又动了鼠标              | 前 2 分钟全算；停表截止线顺延到 **10:04:00**，中间无缝衔接。 |
| **10:03:00** 或 **10:10:00** 才动鼠标  | 只记 **10:00:00 – 10:02:00** 这 2 分钟；中间空闲跳过，从下次操作时刻重新开表。 |
| **10:00:00 – 10:15:00** 前台全屏看网课 | 触发视频播放豁免，15 分钟全程正常计入，不会在 10:02:00 断表。 |
| **10:00:40** 锁屏，**10:01:00** 解锁   | 只记前 40 秒；10:01:00 解锁后仍保持暂停，等下一次键鼠操作才重新开表。 |

## 5. 应用名称识别与页面/文档明细归属

Windows 软件种类繁杂，按“**自动识名 + 分级采明细**”处理，既避免满屏“未知应用”，又守住隐私底线：

### 5.1 软件名称自动识别（无需维护应用白名单）

- **自动读取官方产品名**：拿到前台进程的 `.exe` 路径后，直接读取可执行文件内置的版本元数据（`FileDescription` 或 `ProductName`，例如自动将 `WINWORD.EXE` 识别为 `Microsoft Word`、`Code.exe` 识别为 `Visual Studio Code`、`WeChat.exe` 识别为 `微信`）。仅当个别绿色软件缺失元数据描述时，才回退显示文件名。
- **系统组件归类**：内置一份精简的系统界面过滤表（如 `SearchHost.exe` 搜索框、`ShellExperienceHost.exe` 通知中心、`StartMenuExperienceHost.exe` 开始菜单、`explorer.exe` 桌面与任务栏操作），统一归类为 **`系统桌面操作`**，避免出现一堆晦涩的后台进程名。

### 5.2 页面与文档明细归属（两类来源）

1. **浏览器（通过扩展插件采集）**
   - **异步时序对齐**：Windows 窗口切换事件与浏览器扩展上报焦点之间天然存在几十毫秒通信延迟。允许 **300 ~ 500 毫秒的回溯对齐窗口**——只要扩展随后确认了活动标签页，就把刚切进浏览器的这零点几秒补归给对应网页，避免每次切屏开头都丢成“未识别”。
   - **窗口匹配**：本机仅打开一个浏览器窗口时直接一对一绑定；若同时开了多个窗口或不同账号配置且无法确切对应，则安全退回应用级，该时段记入浏览器总时长下的 **`页面未识别`**。
   - **脱敏与隐私**：只记录域名（如 `github.com`、`bilibili.com`），不记录路径、查询参数或标题，也不提供逐站路径选项。**无痕/隐私模式窗口默认不采集任何页面信息**。
2. **效率工具白名单（提取干净的文档/项目名）**
   - 默认所有普通软件（如微信、QQ、游戏等）**绝不采集窗口标题**，防止聊天对象昵称或私人信息进库，界面直接提示“此应用暂不支持页面明细”。
   - 仅对用户列入**效率白名单**的软件（默认内置 Word / Excel / PPT、VS Code、主流 PDF 阅读器），在本地抓取窗口标题并用规则洗掉软件后缀与完整磁盘路径，只保留干净的文档名或项目文件夹名（例如把 `D:\课题\开题报告.docx - Word` 清洗为 `开题报告.docx`）。

## 6. 数据存储、时间计算与查询

- **精准算时长，标准存时间**：同一采集周期内，使用系统单调递增时钟（如 `GetTickCount64`）计算每个 `[start, end)` 区间的真实经过毫秒数，彻底免疫手动改系统时间或网络校时带来的跳变误差；落库时统一记录标准 **UTC 时间戳 + 本地时区偏移**，跨午夜统计按本地真实 00:00 切分。
- **轻量化本地存储**：数据存入本地 SQLite。主表仅记录`起止时间、状态、应用 ID、可空的页面/文档标识、数据来源`；窗口句柄（HWND）、进程 PID 只在内存里用于实时追踪，不写进主表。
- **幂等写入与异常兜底**：同一事件重复触发不会重复累加时长；正常状态更新与检查点按事务提交。若遇系统崩溃或强制断电，重启后根据最后一个已提交检查点封口，并将断电到重启之间的空白如实标记为 `GAP`（采集缺口）。
- **统一查询模型**：桌面端界面与命令行（CLI）共用一套聚合查询逻辑，支持按时间范围、应用名、页面/文档标识筛选，既能看宏观总时长，也能一键点开查看某款软件下的明细分布与未识别占比。

## 7. 验收测试用例与开发顺序

### 核心验收用例

| 测试场景                  | 预期结果                                                     |
| ------------------------- | ------------------------------------------------------------ |
| **正常办公 + 浏览器切换** | 写代码 10 分钟，浏览器前台 15 分钟（其中看技术文档 8 分钟、刷网页 4 分钟、无痕模式 3 分钟）。软件总计 25 分钟；浏览器下显示文档 8 分钟、网页 4 分钟、页面未识别 3 分钟。 |
| **无操作超时与视频/放映豁免**  | 停手 3 分钟后再动鼠标，只记前 2 分钟；前台全屏播放 20 分钟网课全程不动鼠标，20 分钟全额计入。 |
| **高频切屏防抖**          | 写文档时用 `Alt+Tab` 停留 1 秒切去微信瞄了 3 秒又切回文档。1 秒的 `Alt+Tab` 噪音被直接吞掉；3 秒微信记录在案，但统计图表中自动折叠进文档主任务里。 |
| **隐私隔离**              | 打开微信与好友聊天，同时用 Word 编辑 `毕业论文.docx`。数据库里只记录“微信”总时长，不存好友昵称；Word 下精确记录 `毕业论文.docx` 的使用时长。 |
| **锁屏与异常断电**        | 10:00:40 锁屏、10:05:00 解锁后未动鼠标，仅记前 40 秒；直接拔电源强制关机再重启，断电期间记为 `GAP` 缺口，不虚增任何软件时长。 |

### 实施顺序

1. **第一步（核心底座）**：完成 Windows 前台窗口监听、`.exe` 官方名称读取、系统组件过滤、2 秒采集防抖、2 分钟倒计时（含视频播放豁免）及本地 SQLite 落库。
2. **第二步（明细扩展）**：接入效率软件白名单标题清洗，开发浏览器扩展并与本地服务打通 300~500 毫秒异步窗口对齐。
3. **第三步（展示与联调）**：实现含 5 秒碎片折叠的统计查询接口，接入桌面端图表与 CLI 工具，完成全套实机操作对账测试。







补充可能值得注意的地方

**必须留：窗口标题变了，要跟着更新文档名（原第 2 点）**

- **为什么必须修**：你双击打开一份 Word 文档时，前 0.5 秒窗口刚弹出来，标题往往只显示 `Word`，加载完才变成 `毕业论文.docx - Word`。如果只在刚打开那一瞬间抓一次标题，后面你写两小时论文，记录里全都是“未知文档”。
- **人话规则**：只要当前正在用的软件改了窗口标题，就立刻切一段新记录，把最新的文档名/项目名更新上去。

**必须留：给 AI 写死“怎么判断你在看视频或放映”（原第 3 点）**

- **为什么必须定**：无输入停表需要一个简单、可解释的例外，但不能把所有有声应用都当成视频。
- **人话规则**：只有浏览器明确报告视频正在播放，或 PowerPoint 正在全屏放映时才豁免。音乐、会议和普通声音不算；检测不到明确状态时正常停表。

## 实装记录

Windows 桌面采集迁移至 Rust，界面迁移至 Tauri。固定使用 120 秒停表、2 秒系统切换防抖和 5 秒展示折叠，不开放普通用户调整。浏览器扩展上报 Edge 当前标签页的域名与视频播放状态，PowerPoint 放映沿用窗口识别；普通声音不再触发豁免。播放覆盖范围和时间异常的实际处理见 [Rust 桌面端迁移记录](rust-desktop.md)。
