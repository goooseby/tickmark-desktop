## 显示口径

- 今日复盘按同一个自然日裁剪区间。各设备动态生成时间轴。跨端去重、设备累计与并发按 [报表规则](reports.md) 计算，覆盖不足通过报表明细呈现。
- 应用用时为各设备的应用区间之和。只有来源提供明确的同应用标识才合并。当天该应用有至少一条已识别明细且总时长仍有剩余时，在展开列表最后显示「页面未识别」。全无明细的应用只显示主行。
- 记录明细关闭折叠时按开始时间顺排。折叠只归组同设备、连续且返回同应用和明细的短切换，展开保留原始区间。筛选和汇总使用原始记录。
- 周月图可在各设备日用时堆叠，以及去重和重叠两种视图间切换。设备筛选会同步更新各报表。
- Windows 阈值和标题白名单保存在本机数据库，新版采集器在检查点重新读取。浏览器页面通过独立扩展接入，白名单只用于已启用应用的清洗标题。
- 设备与规则显示 Edge 网页采集的连接状态。双端截图使用独立的设计验收样本，Android 同步尚未接入。

## 截图迭代

1. 四页首轮截图发现子行用时偏到表格最右、长历时被截断、排行榜空白及规则控件过宽。调整列宽和对齐、缩短数字输入框，排行榜按内容高度显示。
2. 第二轮检查发现设置提示跨页残留，并验证到另一台设备的记录会打断短切换分组。提示在导航时关闭，折叠改为先按设备分组。检查了双轨悬浮、窄窗口和暗色模式。
3. 实际 Tauri 窗口读取旧格式 SQLite 时发现一次并发初始化锁冲突。数据库迁移改为单次串行初始化，普通查询走只读连接，再用独立数据库验证。
4. 用同一批样本分别截图核对 Edge 有明细、有剩余时长以及完全没有明细的界面。首轮发现剩余时长沿用了文档图标，改用中性的虚线圆，并收短了主行明细计数。复查确认普通应用没有多余的说明，站点汇总可读取域名。截图保存在 `artifacts/edge-review/`。
5. 电脑、手机、平板样本用于三轨日报与周报验证。首轮趋势误将尚未到来的日期显示为缺测，小时分布缺少色阶说明。复查时淡化未来日期并移除其流水入口，补齐小时图例、每轨用时和逐日设备列。截图保存在 `artifacts/report-review/`。用设备筛选及日期下钻核对显示，用自动化测试验证区间计算和镜像校验。
6. 首页改为分时应用报表。首轮空时段卡片占据大块空间，复查将其收为一行，并验证仅在流水中可展开全天时间轴。用三设备样本检查上午流水筛选、窄窗口和应用时长。截图在 `artifacts/home-review/`。
7. 独立多设备仪表盘成为默认页。首轮截图里手机与平板图标相同，宽窗口的来源列离设备太远。改用不同图标并限制来源面板宽度。以电脑、手机、平板样本验证设备下钻，也复查单机状态。聚合报表议题见 [多设备仪表盘](multi-device-dashboard.md)。

## 界面验收标准

每次改界面，在实际桌面窗口走完主流程并截图。用商用桌面软件的交付要求逐项检查，写下具体问题和修正方案。修正后重拍并逐项核对，有明显问题继续迭代。截图须覆盖默认状态以及适用的忙碌、空数据、错误和恢复场景。

- 一眼能看出当前步骤、主要操作和结果。主要操作有明确的视觉优先级，次要操作摆在它所影响的内容附近。
- 文字层级、间距与对齐有一致规则。检查普通窗、最小窗和深色模式，确认控件、提示及长内容可读。
- 检查 Tab 顺序、焦点去向、快捷键和退出时返回的位置。错误提示贴在出错字段附近，可以直接修正再提交。

### 账号登录的截图迭代

1. 左下角窄浮层同时容纳邮箱、验证码、重发及更换邮箱。首轮截图里表单和报表争夺注意力，验证码步骤的动作缺少主次。保留左下角账号菜单，将登录改成有独立工作区的两步流程。
2. 新工作区首轮截图发现返回链接远离表单，验证码框与通用输入框过于相似。将返回链接对齐表单列，并为验证码框增加六位占位和统一的焦点边框。用普通窗、最小窗深色、输错码和已登录菜单的截图复查。
3. 左上角布局像临时设置表单，双栏布局又让设备说明抢走主操作的注意力。参考 Slack 的两步邮件验证及 Fluent 2 的登录对话框，保留左下角账号入口。验证时在同一个对话框内替换字段、保留下面的工作界面、把主按钮固定在右下。分别检查邮箱格式、带空格验证码粘贴、输错、重发倒计时与关闭后的焦点。 [Slack 登录](https://slack.com/help/articles/212681477-Sign-in-to-Slack-Sign-in-to-Slack) · [Fluent 2 对话框](https://fluent2.microsoft.design/components/web/react/core/dialog/usage/) · [Fluent 2 字段](https://fluent2.microsoft.design/components/web/react/core/field/usage)
4. 对话框复查使用已有报表数据的样本。发现底图太抢眼、关闭键偏淡，降低底图清晰度、加强关闭键，并让浅底操作栏与字段区分开。复拍普通窗、窄窗深色、输错验证码和已登录菜单。
5. 邮箱和验证码改为同时显示，删除常驻说明和步骤切换。首轮截图里发送按钮挤窄了邮箱，倒计时缺少动作说明。复查将发送按钮移到较短的验证码字段旁，并注明倒计时后可重发。验收包含更改邮箱后阻止提交旧验证码。
